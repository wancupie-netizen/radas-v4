# Updates & Support

Baseline: `cb04ffb0c4d3d5f399c237a2bc61ac8ce2af3854` in `wancupie-netizen/radas-v4`.

## Apply locally
1. Stop `npm run dev` with Ctrl+C.
2. Run the supplied PowerShell patch in the project folder. It verifies repo/HEAD and file hashes, creates a backup, applies explicit files and runs local checks.
3. After `UPDATES_SUPPORT_LOCAL=PASS`, paste the copied migration into SQL Editor in Supabase project **fyqvvkpzcwrmyozxlqkw** and run once.
4. Run `supabase/verify-updates.sql`. All 11 rows should be `true`.
5. Run `npm run dev` and review `http://localhost:3000/updates` and `/admin/updates`.

No new packages, environment variables or bucket setup. No wallet/payment/generation changes. No automatic commit/push or production SQL.

## User acceptance
- Login required. Logged-out visit redirects to login.
- Any verified user may read published updates, including zero-credit users who have never topped up.
- Studio has Updates & Support links on desktop and mobile.
- Support opens `https://t.me/radasmalaysia` in a new tab.
- With no updates, show a genuine empty state; failed load shows failure, not empty data. Telegram remains available.

## Admin acceptance
Use the existing approved admin account (`payment_admins`). No new account gains admin rights.
- Open `/updates`, choose **Urus updates sebagai admin**, or go directly to `/admin/updates`.
- Add a title and description. Leave Publish unchecked to save a draft.
- Ordinary users cannot see the draft or use the admin route/API.
- Edit the draft, check Publish and save. The update appears for users.
- Edit, unpublish and delete as needed. First publication date is generated by the database (display MYT). Plain text only, maximum title 120 / description 5000 characters.
- A stale edit fails with conflict. Refresh and open the current version before editing.
- If a save response is lost, the original command/UUID stays available. **Ulang request yang sama** explicitly replays it; there is no automatic write retry.
- Up to 200 active updates. Deleted entries are hidden and retained privately for replay protection/audit.

## Verification and deploy
Local checks: `npm run build`, `npm run check:updates`, `npm run check:auth`, `npm run check:errors`.
Tests use isolated SQL and HTTP/UI fixtures. Live Supabase privileges, admin editing and desktop/mobile appearance require owner acceptance.
After local and SQL acceptance, commit the explicit patch files and push through VS Code. Railway deploys the same V4 service. Verify live `/updates` after deployment.
Auto payment is a separate feature.
